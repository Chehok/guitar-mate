## 실행 조건과 계산

기준 코드는 main의 `87f8e841a2c5720a1b9f12708ce656f375c3b831`입니다. 기준·수정 코드 모두 실제 Tesseract.js 5.1.1 / OEM 1 / eng `4.0.0_best_int`를 실행했습니다. 모델 파일·입력 이미지·분리·이미지 순서·크기 제한·평가 함수를 동일하게 유지했습니다. Node에서 앱과 동일한 JS 함수 `runScoreOCRPasses`를 실행하고 Python/Pillow는 이미지 입출력만 맡았습니다. 정답은 OCR 호출이 끝난 뒤에만 평가 함수에 전달합니다. 저장된 원시 판독을 재처리한 숫자가 아니라 전후 각각 새로 OCR한 결과입니다.

라벨에는 코드별·행별 좌표가 없으므로 이미지별 라벨 행 순서와 OCR 출력 순서를 각각 펼쳐 LCS로 정확 일치 발생 수를 구합니다. 반복 코드도 매번 셉니다. 참조 문자열의 대소문자·괄호·슬래시는 그대로 비교하고 음악 이론이나 이명동음 정규화를 적용하지 않습니다.

일치 앵커 사이의 불일치 구간에서 순서대로 쌍을 이루는 토큰을 오인식으로, 남은 참조 토큰을 누락으로, 남은 출력 토큰을 불필요한 검출로 집계합니다. LCS 동률은 참조 쪽을 먼저 진행하는 고정 규칙을 씁니다. 이는 공간적 검출 평가가 아니며, 반복 코드 주변의 오류 분류는 정렬에 따라 달라질 수 있습니다.

`참조 = 일치 + 오인식 + 누락`, `검출 = 일치 + 오인식 + 불필요한 검출`입니다. Precision=일치/검출, recall=일치/참조, F1=2×일치/(참조+검출)입니다. 모든 결과에서 이 항등식과 별도 Python LCS 계산을 확인했습니다.

export NODE_PATH="$OCR_RUNTIME/node_modules"
