# 기타메이트

코드 추천·튜닝·코드 판별·악보 변환을 페이지별로 제공하는 한국어 기타 연습 도우미입니다. 메뉴 이동은 각 페이지를 새로 열어 방문 통계를 따로 집계할 수 있습니다. [Pretendard Variable 동적 서브셋](https://github.com/orioncactus/pretendard/blob/main/packages/pretendard/docs/en/README.md#variable-dynamic-subset)을 사용하며, 글꼴을 불러오는 동안 시스템 글꼴로 표시합니다. 외부 OCR 도구는 자동 악보 인식 때만 불러옵니다.

첫 화면은 튜닝(`index.html`)입니다. 코드 검색은 `chord-search.html`, 코드 판별은 `chord-identifier.html`, 악보 키 변환은 `score-key-transposer.html`에서 엽니다. Cloudflare Workers 기본 설정에서는 개별 HTML 주소가 확장자 없는 주소로 리디렉션됩니다.

튜너는 70–1000 Hz를 분석하며, 마이크 감도는 기본 8배(1–16배 조절)입니다. 마이크는 HTTPS 또는 localhost에서 사용할 수 있습니다.

홈 화면 추가와 오프라인 사용을 지원합니다. GitHub Pages의 `/guitar-chord/` 같은 하위 경로에 폴더 전체를 배포하세요. 온라인에서 첫 방문 후 서비스 워커의 캐싱이 완료되면 오프라인에서도 사용할 수 있습니다. 앱 파일을 수정해 배포할 때는 `sw.js`의 `VERSION`을 올리세요. 새 버전의 파일이 모두 캐시된 뒤 이전 캐시를 교체하며, 열려 있던 화면은 다시 열거나 새로고침하면 갱신됩니다.

악보 변환은 JPG/PNG(최대 20MB)를 기기 안에서 처리합니다. 업로드 후 공개 PP-OCRv5 모델과 ONNX Runtime Web 1.20.1, 보완 판독용 Tesseract.js 5.1.1을 지연 로드하며 이미지와 인식 결과를 서버로 보내지 않습니다. 공개 파일은 jsDelivr·Hugging Face에서 받으며 새 영역 모델과 런타임 다운로드가 약 20MB 추가됩니다. 이 외부 파일은 서비스 워커의 앱 캐시에 포함하지 않습니다. 오프라인이거나 OCR을 사용할 수 없으면 이미지의 위치를 눌러 코드를 직접 추가할 수 있습니다. 키보드용 가로·세로 위치 입력과 코드 수정 목록도 제공합니다. 직접 추가한 코드와 추천 전주(코드 직접 추가 옆 **추천 전주** 버튼의 팝업에서 넣기)는 마우스·터치로 끌거나 방향키(Shift로 5%)로 옮길 수 있습니다. 전주는 악보 왼쪽 위에 먼저 놓입니다. 추천 전주는 감지한 키의 쉬운 진행, 곡의 첫 코드 진행, 곡 끝 4코드 진행의 세 가지이며 괄호 안 선택 코드와 연속 반복 코드는 한 번만 셉니다. 곡이 V 코드(못갖춘마디)로 시작하면 ii(단조는 iv)에서 이어지게 추천합니다. 전주 소리는 팝업의 재생 템포(50–180 BPM, 기본 120, 4/4박자 한 마디에 코드 하나)로 들을 수 있으며 템포는 새로고침하면 초기화됩니다. 큰 이미지는 긴 변 4096px, 최대 1200만 화소 안으로 줄여 표시·저장합니다.

카포 0–11은 원래 소리를 유지하는 코드 모양으로 변환합니다(예: G에서 카포 1 → F#). 카포 없이 반음 이동은 실제 키를 변경합니다. 키는 코드 빈도와 첫·마지막 코드로 추정하며 직접 고를 수 있습니다. OCR은 정규식·신뢰도·글자 높이·위치·줄 문맥으로 결과를 거르지만 오인식과 누락이 있을 수 있으므로 인식된 코드를 확인하세요. 교체 모드는 주변 배경색으로 원래 코드를 가리고, 위에 모드는 원래 코드 위에 표시합니다. 사진 배경처럼 색이 복잡한 악보에서는 위에 모드를 권장합니다. PNG는 현재 원본 보기 설정을 포함한 미리보기와 같은 방식으로 그립니다. 악보와 수정 내용은 새로고침하면 초기화되며 사용법의 다시 보지 않기 설정만 로컬에 저장합니다.

브라우저 없이 검증:

```sh
node tests/tuner.cjs
node tests/pwa.cjs
node tests/install.cjs
node tests/navigation.cjs
node tests/score.cjs
node tests/chord-filter.cjs
node tests/audio.cjs
node tests/ocr-eval.cjs
node tests/ocr-dataset.cjs
node tests/score-recognizer.cjs
```

reviewed 53장 기준 [누락 복구 실측(2026-11-07)](docs/ocr-recovery-20261107.md)에서 직전 개발본 대비 평가 정확 일치가 204→221/318개, recall은 64.15→69.50%, precision은 96.68→97.36%로 올랐습니다. 누락은 107→91개, 오인식은 7→6개이며 불필요한 검출은 0개입니다. 평가 10장은 최종 코드로 새로 실행했고 개발 42장의 최종 수치는 실제 판독의 필터 재처리로 1,532→1,564/1,914개입니다. 최초 main 대비 평가 일치는 194→221개입니다. 원본·전사·원시 보고서는 저장소 밖에 보관합니다. [2차 모델 추가](docs/ocr-refinement-20261106.md)와 [1차 기록](docs/ocr-reviewed-20261106.md)은 비교 이력이며 모델 재학습은 하지 않았습니다.

기존 Tesseract 단독 벤치마크(새 경로 재현은 2차 개선 기록 참고):

```sh
NODE_PATH=/tmp/ocrt/node_modules OCR_LANG_PATH=/tmp/ocrt \
  node scripts/ocr-eval.cjs --all /tmp/gc-score-round

# 기존 좌표 정답을 사용하는 단일 이미지 평가도 지원합니다.
NODE_PATH=/tmp/ocrt/node_modules OCR_LANG_PATH=/tmp/ocrt \
  node scripts/ocr-eval.cjs .ref/full-score.png tests/fixtures/full-score-chords.json /tmp/gc-score
```

위 명령의 `/tmp/ocrt`는 외부 런타임 예시 경로입니다. 설치 방법은 `scripts/ocr-eval.cjs` 상단을 참고하세요. Python 3 + Pillow는 이미지 입출력만 담당하며 앱과 같은 JavaScript OCR 코드를 실행합니다. `--all`은 `tests/fixtures/scores/01.json`~`11.json`과 기존 full-score를 모두 평가하고 precision/recall 표, JSON, 원본 좌표에 인식 영역을 그린 PNG를 결과 폴더에 남깁니다. 이름·발생 횟수·줄별 순서가 어긋나거나 오탐이 있으면 종료 코드 1입니다. 기본 JSON에는 각 시도의 원문·신뢰도가 있고 `OCR_DEBUG=1`이면 단어별 좌표도 포함합니다. 단일 실행의 정답 JSON과 결과 접두사는 선택 인자입니다.

11장 이미지를 직접 보고 인쇄 코드 **441개**를 줄별로 전사했습니다. 06의 빨간 손글씨 보조 코드는 제외하고, 09의 괄호 코드와 아래쪽 대체 코드도 정답에 포함합니다. 음악 기호 ♯/♭·위첨자 숫자는 #/b·일반 숫자로 정규화하고 괄호는 보존합니다. 정답 JSON의 y는 대략적인 줄 위치이며 11에는 페이지 x 범위도 있습니다. 반복 코드도 매번 세는 줄별 순서 대조를 사용하며, 기존 full-score는 이름과 원본 bbox도 대조합니다. `.ref/`는 `.gitignore`로 제외하며 이미지 자체는 추적하지 않습니다.

검은 코드와 컬러 코드는 오선 다섯 줄을 찾아 그 위의 영역을 읽습니다. 색 가장자리와 위첨자를 보존하고 코드에 붙은 음표 빔을 분리합니다. 흩어진 sus/add/2·베이스 접미사와 괄호를 결합하며, 새 경로는 영역별 실제 모델 판독을 교차 확인합니다. 기존 Tesseract 대체 경로는 반복 글자의 모양 비교도 유지합니다. 인쇄 코드보다 위에 있는 빨간 보조 필기는 별도로 제거합니다. 두 페이지는 왼쪽 전체에서 오른쪽 전체 순서로 반환합니다. 큰 빨간 악보와 오선 검출이 어려운 이미지에는 기존 인식 경로도 유지합니다. 검은 악보는 전체 이미지를 확대하는 작업을 생략합니다.

OCR 보정은 수동 코드 입력과 분리되어 있습니다. 원시 신뢰도와 판독 근거를 유지하며, 새 경로는 임시표·접미사를 여러 형태에서 실제로 읽었을 때만 보완합니다. 겹치는 코드 행 띠에서 추가 영역을 찾고 두 인식기가 같은 문자열을 읽은 개별 코드를 보존합니다. 모델 로드 실패 시 기존 Tesseract 경로를 사용합니다. 기존 대체 경로의 반복 글자 보완에는 `templateSupport`와 `templateReadConfidence`를 별도로 남깁니다. 모바일에서는 여러 차례 판독에 시간이 걸릴 수 있으며 중지와 직접 수정이 가능합니다. 기기·해상도·기울어짐에 따라 새 악보의 결과는 달라질 수 있습니다. 브라우저 검증 범위와 실제 기기 미검증 항목은 누락 복구 실측 기록에 있습니다.

앱 심볼은 기타 피크 안에 넥·사운드홀·브리지를 담은 기타메이트 마크입니다. 표준 라이브러리만 사용하는 `python3 scripts/generate-icons.py`로 앱 아이콘(192/512px), maskable 아이콘(512px), Apple 터치 아이콘(180px), SVG 파비콘과 PNG 파비콘(32/16px)을 함께 재생성할 수 있습니다. 마크는 maskable 중앙 안전 원 안에 배치됩니다.

디자인은 진녹색·크림을 유지하고 Pretendard Variable 글꼴, 모바일 한 줄 탭, 키보드 포커스, 44px 이상 컨트롤, `prefers-color-scheme` 다크 모드와 `prefers-reduced-motion` 설정을 지원합니다. 튜너의 큰 음 표시는 연주 중 멀리서도 읽을 수 있도록 유지합니다.

taste-skill의 Editorial greeting 방향(seed `332781039`)을 바탕으로 크림 바탕과 단정한 패널을 사용했습니다. 4탭 구조와 기타 연습 흐름에 맞춰 사이드바 없이 구성했습니다. Node 회귀 테스트와 Chromium 모바일 viewport 검사를 실행했습니다. 실제 모바일 기기의 검증은 포함하지 않습니다.

정적 디자인 린터가 이모지로 분류한 기존 음악 기호(♭/♯), 패널 제목 경고와 측정 대기 기호(—)는 음악 표기와 UI 의미를 위해 유지합니다.
